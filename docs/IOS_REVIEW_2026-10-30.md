# Ревизия СтройСкан — удобство для строителя

Дата: 30.10.2026. Ветка: ios-more.

## Выполнено в этой серии правок

- **Каркас ГКЛ:** вместо единственного Picker стены — несколько стен по чекбоксам, выбор «Все/Сброс». Есть отдельный эскиз новой ненесущей перегородки с поворотом, длиной и смещением относительно центра LiDAR-комнаты.
- **3D:** геометрическая схема профилей пересчитывается при изменении выбора. Профили показываются в отдельном SceneKit просмотре; это не AR-наложение в реальном времени.
- **Помощник прораба:** примеры задач, определение категории по тексту, ручной выбор вида работ без принудительного переопределения при генерации, сохранение отметок чек-листа на устройстве и ссылка на ИИ для сложных случаев.
- **Главный экран:** офлайн-помощник и нейросети доступны даже при отсутствии RoomPlan/LiDAR; кнопки реального скана показываются только при поддержке устройства.
- **ИИ-наставник:** инструкции для сложных комплексных заявок (последовательность нескольких профессий, этапы закупок, вопросы по исходным данным, объяснения новичку).
- **Существующие возможности сохранены:** сканы/досъёмка, очередь бота, PDF/DXF, 3D, инженерные точки и трассы, смета, отделка.

## Обнаруженные ограничения и следующие задачи

1. **Каркас ГКЛ — эскиз, а не рабочая документация.** Не рассчитывает подвесы, соединители, конкретную систему производителя, усиление проёмов, пожарные узлы, нагрузки, технологические отступы, раскрой по длинам. Сумма длин профилей и эквивалент 3-метровых заготовок пока только грубая оценка.
2. **Новая перегородка:** размещается ползунками, проверяется попадание оси внутрь полигона пола, но не поддерживает чертёж точным касанием на плане, дверные проёмы и полноценную BIM-коллизию.
3. **Реальное AR-наложение каркаса в процессе скана:** не реализовано. Для него требуется сохранить и валидировать мировые якоря, выбор стены в RoomCaptureView, контроль дрейфа, накладки проёмов и производительности.
4. **Сантехника/электрика:** авто-трасса — только эскиз между расставленными точками. LiDAR не видит скрытые коммуникации, не выполняет гидравлический, электрический и конструктивный расчёт.
5. **Офлайн-помощник:** 15 технологических карт, не произвольный генеративный интеллект. Для нестандартных заявок предусмотрен ИИ по сети с отдельным ключом и расходом кредитов.
6. **Проверка на iPhone:** CI подтверждает компиляцию, но не точность LiDAR, качество навигации, плавность SceneKit, сохранение при смене ориентации или надёжность установки IPA.
7. **Установка:** сборка в GitHub Actions создаёт неподписанный IPA; для Windows нужна подпись Apple ID, например в Sideloadly, и распознавание телефона через драйверы Apple.

## Следующий план приоритетов

- P0: проверить последнюю GitHub Actions сборку и исправить ошибки компиляции, если будут.
- P0: протестировать реальный iPhone: 1) скан с углом и дверью, 2) выбор нескольких стен, 3) новая перегородка с положением и углом, 4) потолочная схема, 5) закрыть/открыть помощника, проверить чек-лист, 6) экспорт.
- P1: сделать 2D-редактор трасс/перегородок касаниями с привязкой к стенам, размерами и отменой.
- P1: полноценные монтажные схемы систем ГКЛ по производителям, раздельная спецификация UD/CD/ПН/ПС, раскрой и подвесы после проектных параметров.
- P1: общая сущность «Проект ремонта» со стадиями, связями задач, закупками, выполненными работами и резервными копиями.
- P2: AR-превью каркаса во время/после скана с контролем качества геопривязки и возможностью отключить слой.
- P2: интеграционное тестирование на нескольких iPhone и проверка CI/доступности IPA.

## Важное

Ни схемы каркаса, ни трассы сетей не должны обозначаться как утверждённые для монтажа без проверки проектом и квалифицированным специалистом.
